# Re:Arcaea card

用于记录 Arcaea 游玩成绩的静态网页工具。内置谱面信息来自 Arcaea 中文 wiki。

## 本地使用

在项目目录启动静态服务器，例如 `python3 -m http.server 8000`，然后打开 `http://localhost:8000/`。请使用 HTTP 访问；首页需要加载本地曲库 JSON。

## Yurisaki CSV 导入

存档页可同时选择 `all_scores.csv`、`best_scores.csv`、`ratings.csv`，点击“导入 CSV”。

- 成绩按 `SongId + Difficulty` 合并并保留最高分；同分保留时间较晚的记录。原有手动成绩参与合并。
- 保存 CSV 原始分数、定数、单曲 Potential、判定和毫秒时间戳，不依赖内置曲库重新计算。曲库缺失的曲目显示 SongId。
- 历史成绩按曲目、难度、时间戳、分数去重；账号记录按时间戳去重。同一条记录的新导入字段覆盖旧字段。
- 支持 UTF-8 BOM、CRLF、带引号和逗号的字段；无效行会被跳过并报告。无法识别的文件或文件结构错误会取消该批导入。
- 数据保存在浏览器 localStorage。存档以 JSON 文件下载和上传，包含成绩及账号历史；旧版字符串可保存为文本文件后上传。清空存档也会清空历史。
- CSV 是本地输入，不要将个人成绩文件提交到仓库。

## Potential 涨幅

首页左侧显示最近游玩和排行，右侧浮动侧栏切换新版 B50 / 旧版 B30；选择 Potential 涨幅后仅显示历史内容。在存档页导入 `ratings.csv` 后历史数据同步更新。旧地址 `potential.html` 会打开该标签页。

按 `Timestamp` 排序，提供起点、终点、净变化、最高值、真实时间轴曲线、日期筛选和变化明细。明细每次显示 100 条，可继续加载。日期显示与筛选均使用浏览器本地时区，结束日期包含整天。

`UserRating` 默认除以 10（例如 `129.8 → 12.98`）；该默认值基于本次 Yurisaki 导出样本，可选择原值或除以 100。单曲 `Potential` 不做此缩放，也不当作账号 Potential。区间净变化为最后一条减第一条；逐次变化相对于区间内上一条记录。曲线连线不补全未记录的历史。

首页侧栏切换两种计算结果（按照用户指定的换算规则）：

- 新版：原始单曲 Potential 排序，`(B10 总和 + B50 总和) / 60`。
- 旧版：所有成功通关的单曲 Potential 减去 0.2，再独立排序，`(B10 总和 + B30 总和) / 40`。失败成绩不扣减。
- B10 是相应排序的前 10 条，包含在该版 B30/B50 内；数量不足时按 0 补足，分母保持 40/60。原始值不被覆盖，不会因重复导入或刷新重复扣减。
- 导入保留 `ClearType`（0 失败，1/2/3/4/5 成功）。缺少该字段时默认 Track Complete。手动录入默认 Track Complete，并支持选择其他成功通关类型。
- 账号历史仍只使用 `ratings.csv`，不受新版/旧版换算影响。

## 验证

无需安装依赖，运行 `node tests/csv.test.cjs` 检查解析、无效数据、最高分合并、时间排序、去重及历史隔离。

可传入本地导出目录 `node tests/csv.test.cjs /path/to/export`，对本次样本执行额外断言（859 条成绩历史、439 张谱面、223 条账号记录）。测试不修改输入文件。

运行 `node tests/potential.test.cjs` 验证两种公式、通关扣减、重新排序、固定分母以及旧数据补全。可选传入导出目录核对实际结果。

运行 `node tests/history.test.cjs` 检查首页历史组件与导入、日期筛选、存档保存事件的联动（模拟 DOM，不替代真实浏览器视觉检查）。

曲库已按用户粘贴的维基表格更新 552 条曲目记录的定数资料。物量在原曲库基础上新增本地谱面核实的 89 张，剩余 15 张未知；详见 [曲库核对](docs/catalog-audit.md) 和 [来源快照](static/wiki-constants.json)。

运行 `node tests/catalog.test.cjs` 检查定数覆盖、同名曲区分、新曲查找及不同难度的排序。

运行 `node tests/archive.test.cjs /path/to/export` 验证文件存档往返、旧格式兼容及无效文件保护。
